# ChainMind 当前状态与验收

日期：2026-09-13。面向全栈 / AI 应用开发作品集与 GitHub 展示。

## 结论

最值得聚焦的方向是“可追溯的多角色讨论与人工决策工作台”。源码覆盖面较大，
但部分扩展功能尚未形成用户闭环。展示应从一个清晰场景、实际页面、可复现安装和
可解释的技术取舍入手，再用真实模型回归补强可信度。

展示改进已合入主分支。本次在隔离工作区完成品牌统一、历史清理和冗余整理。
原工作区的三个文件删除，以及另一开发工作区的未提交内容均保留；下面的代码验证
对应完整的展示版本，不代表这些未提交删除已修复。

## 本地验证

环境：macOS arm64，Node.js 22.22.3，npm 10.9.8。

- 干净 `npm ci` 成功。
- TypeScript 与 Next.js 生产构建通过，`/demo` 和 `/workspace` 路由均生成。
- Vitest：12 个测试文件，81 项通过。供应商请求使用测试替身；不证明真实模型质量。
- ESLint：0 errors、0 warnings；原有 25 条未使用变量警告已清理。
- `npm audit`：初始 32 项（4 critical），最终 0 项；仅代表当前依赖审计结果。
- 本轮浏览器回归：新版 Logo 在工作台和双语示例正常显示；390 px 页面无横向溢出，终端使用本地 xterm 样式，未检测到页面错误。
- 品牌导出检查：SVG/PNG 尺寸正确，ICO 包含 6 种尺寸；macOS `iconutil` 可解析 ICNS。尚未验证签名安装包。
- 当前文件的常见密钥格式检查通过；不覆盖 Git 历史，也不代替密钥撤销。
- 首轮 Electron 44.3.0 使用临时 user-data 目录启动：实际 `/workspace` 页面加载，preload LLM 方法、配置 IPC、关闭 Node integration 与 SQLite 15 张表均检查通过。外部 HTTP 请求在该检查中被阻断。
- 配置向导：用浏览器拦截返回失败响应，验证长字符串密钥不会被显示为已验证；该检查没有向真实供应商发请求。
- 浏览器示例：生产构建下验证双语切换、A/B 方案改变内容、阶段导航与下载。下载的 Markdown 包含所选方案、全部 5 阶段和示例声明；1440 px / 390 px 布局检查通过，无横向溢出、模型请求或外部资源加载。

GitHub CI 结果以 [Actions](https://github.com/djblack1209-coder/ChainMind/actions) 为准。
本地通过不等于远程 CI 已通过。

## 历史清理

维护者已确认旧凭据轮换。使用 `git-filter-repo` 移除了历史预设文件并替换已知
凭据；重写前留有仅本地可访问的恢复备份。远端主分支已更新，已合并展示分支已删除。
新克隆的主分支和本地全部 Git 对象均做了旧凭据精确匹配检查，结果为 0。
本机未运行的旧 `.next` 构建缓存中还发现副本，已删除该可重新生成的缓存。

GitHub 的旧 PR 引用仍由平台保留，其他人的克隆和平台缓存无法通过普通 Git 推送
擦除。旧克隆应重新克隆或专门迁移，避免合并旧历史重新引入已删除内容。
参考 [GitHub 历史清理说明](https://docs.github.com/en/authentication/keeping-your-account-and-data-secure/removing-sensitive-data-from-a-repository)。

## 尚未闭环

| 优先级 | 问题 | 影响与下一步验收 |
| :--- | :--- | :--- |
| P1 | 真实模型协作效果 | 需用自己的凭据彩排完整流程，并评估质量、成本、停止与恢复 |
| P1 | 大组件编排 | `ChainPanel` 仍承载较多状态转换、网络和 UI 逻辑；应拆分并测试阶段转换 |
| P1 | MCP UI 与后端不一致 | 后端为 stdio 配置；面板仍偏 URL/本地展示，需接通真实配置、调用与诊断 |
| P1 | 发行与许可 | 图标与更新仓库已补齐；根许可证、归属确认、签名、正式发布及各平台安装验收仍待完成 |
| P1 | 密钥与工具边界 | 浏览器回退口令较弱；桌面 secret 是本机文件，工具/插件不是已认证 OS 沙箱 |
| P2 | DAG 用户入口 | 引擎和节点组件存在，完整编辑器尚未挂载 |
| P2 | 团队与商业化 | 无已验证的多租户隔离、团队同步、配额、计费或商业使用数据 |

更完整的逐项标准见 [roadmap.md](roadmap.md)。没有把健康接口、示例内容、旧报告
或包版本号当作生产交付证据。

## 自建价值与传播

与成熟平台相比，当前更适合聚焦桌面协作体验与工程取舍的展示，而非功能数量竞争。
官方参照：[Dify](https://github.com/langgenius/dify)、[Flowise](https://docs.flowiseai.com/)、
[AutoGen](https://github.com/microsoft/autogen)。这是一项定位判断，不是性能对标结果。

先围绕“3 人团队代码评审”这个可复现案例收集反馈，再决定扩展方向。可观察指标是：
能否独立安装、是否完成首次试用、问题是否可复现、用户是否回来使用。Stars 是关注信号，
不能代替使用效果；本轮没有虚构用户量、评测分数或增长承诺。
